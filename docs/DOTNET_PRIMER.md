# C# / .NET / WPF primer for this codebase

This guide is for developers who know another language (JavaScript, TypeScript, Python, Java) and have never used .NET. It covers only the concepts this repository uses, with examples from the repository. The structure of the bot is explained in [`ARCHITECTURE.md`](ARCHITECTURE.md).

## Tooling

| .NET | Similar to |
|------|-----------|
| **.NET SDK** (`dotnet` CLI) | Node and npm together: compiler, runtime and package manager |
| **Solution** (`TravBotSharp.sln`) | A monorepo workspace that groups several projects |
| **Project** (`*.csproj`) | `package.json`: target framework, dependencies and build options |
| **NuGet package** | An npm package |
| `packages.lock.json` | `package-lock.json`. `dotnet restore --locked-mode` installs exactly the versions it lists. |
| `bin/`, `obj/` | Build output, like `dist/`. Do not commit it. |

Common commands:

```bash
dotnet restore              # install packages
dotnet build                # compile
dotnet run --project WPFUI  # start the app
dotnet test                 # run the tests
```

In this solution, `WPFUI` is the executable and depends on `MainCore`, which is a class library. `MainCore.Test` depends on `MainCore`.

**Editors:** Visual Studio 2022 or newer, and JetBrains Rider, give the best experience: debugger and XAML designer. VS Code with the *C# Dev Kit* extension also works.

## C# language features used here

### Namespaces and global usings

`namespace MainCore.Tasks { ... }` groups types, like a module path. `using X;` imports a namespace, like `import`.

`MainCore.csproj` declares `<Using Include="..." />` entries. These are **global usings**: they are imported in every file of the project. This is why most files do not show `using FluentResults;` or `using Microsoft.Playwright;`. Note that `ILogger` is an alias for `Serilog.ILogger`.

### Classes, records and keywords

```csharp
public sealed partial class OpenBrowserCommand(IChromeBrowser browser, IDbContextFactory<AppDbContext> contextFactory)
{
    public sealed record Command(AccountId AccountId, AccessDto Access) : IAccountCommand;
    private async ValueTask HandleAsync(Command command) { ... }
}
```

- `sealed`: no other class can inherit from this class.
- `partial`: the class is split across several files. Here the second part is **generated by a source generator** at compile time (see [Attributes and source generators](#attributes-and-source-generators)).
- `(IChromeBrowser browser, ...)` after the class name is a **primary constructor**. The parameters are available everywhere in the class. This is how dependency injection gives the class its dependencies.
- `record`: an immutable data class with value equality, like a frozen object. `record Command(AccountId AccountId, ...)` creates the properties, the constructor and equality in one line.
- `: IAccountCommand`: the record implements an interface. `:` is used for both `extends` and `implements`.
- A class declared inside another class is a nested type. Callers refer to it as `OpenBrowserCommand.Command`.

### Types, `var` and nullability

- C# is statically typed. `var x = ...` lets the compiler infer the type, but the type is still fixed.
- `string?` means the value can be `null`. This project treats nullable warnings as **errors**, so the compiler forces you to handle `null`.
- `AccountId` and `VillageId` are **strongly typed IDs**: small wrappers around `int`. The compiler rejects a `VillageId` where an `AccountId` is expected.

### Generics and constraints

```csharp
public void AddOrUpdate<T>(T task, bool first = false) where T : AccountTask
```

`<T>` is a type parameter, as in TypeScript. `where T : AccountTask` restricts `T` to `AccountTask` or one of its subclasses. `bool first = false` is an optional parameter, and callers can name it: `AddOrUpdate(task, first: true)`.

### async / await

```csharp
private async ValueTask<Result> HandleAsync(Task task, CancellationToken cancellationToken)
{
    var result = await toBuildPageCommand.HandleAsync(new(task.VillageId, plan), cancellationToken);
    ...
}
```

- `Task<T>` and `ValueTask<T>` work like a JavaScript `Promise<T>`. `await` works the same way.
- **`CancellationToken`** is passed down through every async call. When the user pauses the account, the token is cancelled, and the code checks `cancellationToken.IsCancellationRequested` to stop early. It works like an `AbortSignal`.
- In this repository, the bot's own task classes have a nested class called `Task`, for example `UpgradeBuildingTask.Task`. Do not confuse it with `System.Threading.Tasks.Task`, the promise type.

### Target-typed `new` and deconstruction

```csharp
await handler.HandleAsync(new(task.AccountId, task.VillageId), ct);
var (_, isFailed, plan, errors) = await getBuildPlanCommand.HandleAsync(...);
```

- `new(...)` without a type name creates an object of the type the parameter expects. Here that type is the nested `Command` record.
- `var (a, b, c) = x;` is **deconstruction**, like `const [a, b, c] = x` in JavaScript. `_` discards a value. A `Result<T>` deconstructs into `(isSuccess, isFailed, value, errors)`.

### Extension methods

```csharp
// classic syntax
public static int ByName(this AppDbContext context, VillageId villageId, VillageSettingEnums setting) { ... }

// C# 14 "extension block" syntax, also used in this repository
extension(AppDbContext context)
{
    public int ByName(AccountId accountId, AccountSettingEnums setting) { ... }
}

// call site, the same for both syntaxes:
context.ByName(accountId, AccountSettingEnums.TaskDelayMin);
```

An extension method can be called as if it were a method of another type, here `AppDbContext`. The classic syntax marks the first parameter with `this`. The newer `extension(...)` block declares the extended type once for a group of methods. `Infrasturecture/Extensions/GetSettingsExtension.cs` uses both.

### LINQ

```csharp
errors.OfType<NextExecuteError>().OrderBy(x => x.NextExecute).ToList();
```

LINQ is like JavaScript array methods: `Where` = `filter`, `Select` = `map`, `First` = `find`, `Any` = `some`. `x => ...` is a lambda, like an arrow function. When it is used on the EF Core database context, the same LINQ code is **translated to SQL**.

### Pattern matching and `switch`

```csharp
switch (task)
{
    case LoginTask.Task loginTask:
        ...
}
```

This checks the runtime type and casts in one step. `CustomServiceScopeFactory.Execute` uses it to send each task to its handler.

### Attributes and source generators

`[Handler]`, `[RegisterSingleton<T>]` and `[Reactive]` are **attributes**, similar to decorators. In this project they mostly feed **source generators**: compile-time plugins that write extra C# code. That is why the classes are `partial`:

| Attribute | Generated code |
|-----------|----------------|
| `[Handler]` (Immediate.Handlers) | A nested `XCommand.Handler` class that runs the behavior pipeline and then your `HandleAsync`. It is also registered in dependency injection. |
| `[RegisterSingleton]` / `[RegisterScoped]` (Injectio) | The registration lines in `services.AddMainCore()` |
| `[Reactive]` (ReactiveUI) | A property that notifies the UI when it changes |
| `[Mapper]` (Mapperly) | `ToDto()` / `ToEntity()` mapping code |

To read the generated code in Visual Studio or Rider, open *Dependencies → Analyzers → (generator name)* under the project. You can also use "Go to definition" on `Handler`.

## Dependency injection (DI)

The app does not create services with `new`. Each class declares what it needs in its constructor, and the **DI container** (`IServiceProvider`) builds the objects. The container is configured in `MainCore/AppMixins.cs`.

There are three lifetimes:
- **Singleton**: one instance for the whole app, for example `TaskManager` and `ChromeManager`.
- **Scoped**: one instance per *scope*. This app creates one scope per task run, bound to an account. Inside that scope, `IChromeBrowser` returns that account's browser.
- **Transient**: a new instance every time it is requested.

## Result instead of exceptions

```csharp
var result = await someCommand.HandleAsync(...);
if (result.IsFailed) return result;
if (result.HasError<StorageLimit>()) return Stop.Error.WithErrors(result.Errors);
return Result.Ok();
```

`Result` comes from FluentResults. A method returns either a success value or a list of `Error` objects, and the caller checks the outcome. Exceptions are only used for bugs and unexpected failures.

## EF Core (database)

EF Core is an ORM, like Prisma or TypeORM.
- Each class in `Entities/` is a table. Each `DbSet<T>` in `AppDbContext` is a queryable table.
- You query with LINQ: `context.Villages.Where(x => x.AccountId == id).ToList()`.
- You write by changing objects and calling `context.SaveChanges()`.
- `IDbContextFactory<AppDbContext>` creates short-lived contexts: `using var context = contextFactory.CreateDbContext();`. `using` disposes the context at the end of the block, like `try/finally` with a close call.

## WPF and XAML

WPF is the Windows desktop UI framework.

- **XAML** (`*.xaml`) is XML markup for the UI, similar to HTML. `<Button x:Name="SaveButton" Content="Save" />` declares a button. `x:Name` makes it available in C#.
- **Code-behind** (`*.xaml.cs`) is the C# class for that XAML file. Both files are `partial` parts of the same class.
- **Resources and styles** (`App.xaml`, `WPFUI/Styles/`) work like global CSS. This app uses the MaterialDesign theme.
- **Converters** (`WPFUI/Converter/`) change a value for display, for example a `bool` to `Visibility`.

## MVVM with ReactiveUI

MVVM separates the screen (**View**) from its state and logic (**ViewModel**).

- The **ViewModel** (`MainCore/UI/ViewModels/...`) holds the state and the commands. `[Reactive]` properties notify the UI when they change, similar to `useState` or Vue refs.
- The **View** binds its controls to the ViewModel in the code-behind:
  ```csharp
  this.WhenActivated(d =>
  {
      this.Bind(ViewModel, vm => vm.Name, v => v.NameBox.Text).DisposeWith(d);   // two-way
      this.OneWayBind(ViewModel, vm => vm.Items, v => v.List.ItemsSource).DisposeWith(d);
      this.BindCommand(ViewModel, vm => vm.Save, v => v.SaveButton).DisposeWith(d);
  });
  ```
  `WhenActivated` runs when the view appears. `DisposeWith(d)` removes the bindings when the view closes, like a `useEffect` cleanup.
- A **`ReactiveCommand`** is an action a button can run. It can be async, and it can be disabled while it is running.
- **Observables (Rx)** are streams of events. `rxQueue.GetObservable<TasksModified>()` emits an event every time background code calls `rxQueue.Enqueue(new TasksModified(...))`. The ViewModel subscribes and refreshes. This is how the bot loop updates the UI without referencing it.
